# 個人資料保護影響評估（DPIA）骨架

健康大數據 App 一期 PoC｜版本 0.1（2026-10-30）｜狀態：**草稿，待法制與資安單位審查**
本文件依 SPEC §11 由系統規格產生骨架；「待填」處需由業務、法制與資安單位補齊並簽核。

## 1. 處理概述

| 項目 | 內容 |
|---|---|
| 目的 | 健康促進：每日個人健康報告、運動提醒與點數激勵；公衛單位以去識別化群體統計規劃資源與關懷 |
| 非目的 | 醫療診斷、保險或僱用評估、行銷剖析。系統定位為健康促進工具，不申請 SaMD；輸出不得構成診斷（C-7） |
| 資料主體 | 轄區參與民眾（含 65 歲以上長者）、其授權家屬、據點人員與志工、特約商家 |
| 控制者 | 待填（例：○○市政府衛生局） |
| 受託者 | 待填（系統維運廠商；LLM 服務提供者 Anthropic，見 §5） |
| 法律依據 | 個資法第 6 條特種個資（醫療、健康檢查）：當事人書面同意（逐來源、逐項目，§3）；公務機關執行法定職務必要範圍內之統計（去識別化） — 待法制確認 |

## 3. 同意與當事人權利

- **逐來源、逐項目同意**（`/consents`）：每一項都可以不授權；引導畫面預設不勾選。每個來源附白話說明「誰看得到什麼」與「撤回後會失去什麼」。
- **撤回**：確認文案只有「確定要撤回嗎？撤回後您將失去：…」，不得勸留；撤回即停止拉取，並在 24 小時內刪除該來源資料、雙生快照、引用該來源的報告與對話（立即執行＋每 10 分鐘補做）。
- **高風險動作需本人確認**（C-5）：預約、分享給家屬、兌換、撤回授權、報名活動（報名會把姓名與電話交給主辦據點）；確認 24 小時內有效。Agent 無法自行確認。
- **以健康狀況推薦（M8）**：活動與店家推薦只使用本人已授權的項目（例如授權據點血壓才會出現血壓相關理由）；理由只在 App 內顯示並經 C-7 過濾，推播只有活動名稱、時間、地點與點數；本人可在「推薦偏好」關閉活動推播。
- **家屬守護圈**：本人以家屬的守護碼建立分享（需確認）；家屬只看到狀態一句話、風險等級、是否有待辦，**沒有任何數值**；本人可隨時收回、立即生效。
- **查詢與更正**：本人可在 App 查看報告、雙生快照、點數流水、通知、授權歷程。資料匯出與更正流程 待填。

## 4. 資料流與分區

```
民眾授權資料 ──(Adapter＋同意閘門)──▶ 可識別區 idn ──(D1 單向聚合，n ≥ k)──▶ 去識別化區 anon
                                          │                                        │
                       A1（idn_user_scoped，RLS 只見本人）          A2／A3／A4（anon_reader，只讀 anon）
                                          │                                        │
                                   民眾 App、家屬摘要                         公衛儀表板
                                          │
          care_rules（idn 內執行，只輸出代號）──▶ 據點端以任務編號解碼（逐次稽核）
```

- **C-1**：兩區之間沒有任何 JOIN；靜態掃描（`make check-schema`）、執行期攔截、DB 權限三道防線。
- **C-2**：機關側 Agent 的 DB 帳號只有 anon 權限（連線測試）。
- **C-4**：聚合結果每格 n ≥ k（預設 5）；加總與子格相減可推回時做次要遮蔽。
- **C-8**：輿情在落地前移除帳號、名稱、頭像、@提及、電話、Email。

## 5. 風險評估

| # | 風險 | 可能性 | 影響 | 現有控制 | 殘餘風險／待辦 |
|---|---|---|---|---|---|
| R1 | 機關端從群體統計反推個人 | 中 | 高 | k-匿名（n ≥ 5）＋次要遮蔽；沙箱 SQL 經中介軟體、聚合必須輸出人數；查詢編號留存可稽核 | 多次差分查詢仍可能推估：建議查詢預算與異常查詢告警（二期） |
| R2 | 可識別區與去識別化區被串接 | 低 | 高 | C-1 三道防線；八條約束測試每個里程碑必過 | 新增程式須維持測試；定期權限盤點 |
| R3 | A1 越權讀取他人資料或擴大授權 | 低 | 高 | RLS（只見本人）；runtime 注入身分與授權範圍、模型不可修改；工具逐次比對實際授權（C-3） | — |
| R4 | Agent 未經同意執行預約／分享／兌換／撤回 | 低 | 中 | 確認狀態機（C-5）；Agent 傳入的確認參數一律剝除 | — |
| R5 | A1 回覆被當成診斷 | 中 | 高 | 疾病斷言黑名單逐句過濾（C-7）；每個建議附「依據」；定位聲明 | 黑名單需醫事人員定期審閱；LLM 新說法需持續測試 |
| R6 | 送往 LLM 的資料外洩 | 低 | 高 | 不送姓名、電話、地址、身分證；只送年齡層與授權範圍內的健康摘要 | 待簽 DPA、確認資料保存與訓練政策；評估在地部署 |
| R7 | 關懷代號被濫用解碼 | 中 | 高 | 解碼限據點人員、限本據點、必附任務編號、逐次寫入 append-only 稽核；任務單不含健康資料 | 建議定期稽核解碼次數異常（二期儀表） |
| R8 | 家屬看到過多資訊 | 低 | 中 | 摘要層固定三欄、移除數字、讀取寫稽核；本人可隨時收回 | — |
| R9 | 商家推論兌換者身分或健康狀況 | 低 | 中 | 核銷只回品項與點數；月成效年齡層 < k 遮蔽；商家看不到任何健康資料 | 小商家客群固定時仍可能熟人辨識：教育訓練 |
| R10 | 輿情語料含個人資訊 | 中 | 中 | 落地前去識別（C-8）；只採白名單公開來源；只做聚合不建個人畫像 | 摘要中仍可能出現可識別描述：人工抽查 |
| R11 | 撤回後資料未刪除 | 低 | 高 | 撤回立即刪除＋排程補做；刪除任務與筆數寫稽核 | 備份中的資料保留期限 待填 |
| R12 | 帳號被盜用 | 中 | 高 | bcrypt、登入速率限制、短效 token；量測 QR 10 分鐘有效 | 正式環境導入 OIDC／多因子（TW FidO） |
| R13 | 分析沙箱逃逸 | 低 | 高 | 子行程、無網路、60 秒、獨立暫存目錄、不給 DB 連線（資料以檔案傳入） | 一期非強隔離：二期換容器（gVisor 等） |
| R14 | 點數作弊或帳本竄改 | 中 | 低 | 防作弊規則標記待審、人工放行；帳本 append-only；對帳檢查 | — |
| R15 | 推播或推薦理由洩漏健康狀況（M8） | 中 | 中 | 推播不含健康理由；理由只在 App 內、經 C-7 過濾；每週推播上限 2 則、可關閉 | 活動名稱本身可能透露主題（例：血壓講座）：上架時避免過度具體的病名 |
| R16 | 活動參與者被識別（M8） | 中 | 中 | 報名名單只給主辦據點（姓名遮罩、查看留稽核）；機關端報名數 < k 只顯示「少於 k」；參與率經 deidentify 聚合（n ≥ k） | 小型活動現場仍可能熟人辨識 |
| R17 | 公開公告擷取錯誤或含個資（M8） | 中 | 中 | 白名單來源；落地前去識別；擷取結果一律待審，機關人員核對後才上架 | 公告內文中的承辦人稱謂（例：王小姐）不在去識別範圍：人工審核時刪除 |

## 6. 安全措施摘要

傳輸 TLS（正式環境）；敏感欄位應用層 AES-GCM 加密（金鑰於環境變數／KMS）；密碼 bcrypt；角色分離的 DB 帳號與 RLS；稽核日誌 append-only（DB trigger 禁止 UPDATE／DELETE）；API 速率限制；前端不保存健康資料於快取（service worker 不快取 `/api`）。
